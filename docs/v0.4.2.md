# v0.4.2: ready for a wider beta

Status: **being built** (owner, 2026-10-04). A patch release that fixes everything a pre-beta bug hunt found in [v0.4.1](releases/v0.4.1.md), before a larger beta.

## Scope (owner, 2026-10-04)

Four testers used v0.4.1 by role on a copy of the reference data (platform admin and auditor; a team owner and editor building an assistant; members, signed-out visitors, phones and keyboard; a visual sweep of every page at five widths) and filed 119 findings; the owner added two. After merging duplicates: 0 P0, 9 P1, 24 P2, about 70 P3. **All of them are in v0.4.2** (owner: nothing has been widely released yet). axe found no violations on any page tested.

The findings, with steps and screenshots, were kept with the test run; each is summarised in the milestone that fixes it below, under its tester ID (AD admin, BU builder, US users, VI visual, OW owner).

## Owner decisions

- **Scope:** every finding, P1 to P3 (2026-10-04).
- **OW-2, a Reranking page (option A):** reranking gets its own page, **Admin → Models → Reranking**, always in the sidebar like SystemOne: its status (on/off, model and health, candidates, time limit, agents that turned it off), a setup guide when nothing is set up (a connection that serves `/rerank` → a model of kind Rerank → choose it, with a button for each step and which are done), the settings (moved here from the Models page's dialog), a test with a sample query, and "Reranking: off · Set up" / "on · <model>" in Admin → Overview → Features. Before, its settings appeared only as a notice on Admin → Models once a rerank model existed, so nothing said reranking existed.

## As built: M5

The app shell, shared components, phones and bitop-ui (bitop-ui `main` at the commit named in the merge notes; `npx bitop update` brought `core`, `breadcrumbs`, `table`, `data-table`, `tabs`, `toggle-group`, `card`, `popover`, `dialog`, `sheet` and `tag-input`).

- **AD-01** Save conflicts: `useRevisionForm` (`components/templates/revision-form.ts`) holds a settings form over a revisioned object; `SettingsPage` (and `RevisionSaveBar` for forms with their own layout) shows what changed elsewhere and offers **Overwrite with mine** / **Discard mine and load theirs**. The edits survive a 412 and a change loaded while editing; fields the person didn't touch take the other version; their own save is recognised by content (allowing for trimmed text). A 412 refetches every query (`main.tsx`) and its message no longer says to reload. Every `SettingsPage` form with If-Match uses it, and the `key={revision}` remounts that threw the edits away are gone (admin team settings, costs, retention, maintenance, break-glass, parsing, SystemOne, moderation, team and platform limits, team general, knowledge base, source, evaluation set). Dialogs (`FormDialog`) keep their edits already and now get the new 412 message; the agent editor has its own conflict flow (M2). Unit, page and e2e tests (`save-conflict`).
- **AD-03, VI-03** The session gate keeps the app once the session has loaded (a failed refresh no longer replaces it). Before it loads, a 429 shows a page ("Too many requests", a countdown to the next try after `Retry-After`, **Try again now**); other failures get the same page with **Try again**. `GET /v1/me` retries a rate limit until it lifts, other queries twice, always after `Retry-After` (at most 60 s; a team's daily limit isn't retried). The Overview's 28 requests are M4's page; the shell's polls (attention, notifications, maintenance, break-glass) already pause in background tabs.
- **AD-11, VI-32** bitop-ui `Breadcrumbs` keep one line: crumbs shrink, a long one is cut with an ellipsis and its full text is the `title`. On a phone every trail of more than two crumbs collapses to first › … › last.
- **AD-22** The Connections Models link is named "2 models on <connection>"; each MCP tool's **Input schema** button includes the tool's name (both one-line page changes, M4's files). Date fields are native `<input type="date">` with their labels: Chrome names their segments "Month/Day/Year" itself, and the duplicate "Dismiss" buttons in combobox popups are Base UI's hidden dismiss controls for screen readers; neither is ours to change.
- **AD-30** ⌘K lists every admin page's other tabs ("Costs › Settings", "Retention › Runs", "Limits › Ingestion"; `admin-tab-commands.ts`), so multi-word queries find them, and "health"/"failing" offer **Failing models** and **Failing connections** (the lists filtered to Failing). Record search was already fine.
- **AD-32** The sidebar starts as the icon rail below 1100 px (following the window until the person toggles it; the choice is remembered as before). bitop-ui `DataTable` pins its row-actions column to the end edge (`stickyEnd`), with a shadow while columns scroll under it.
- **AD-39** Owner question, not changed.
- **VI-15** Agent cards (Home, Discover agents) give the clamped description its full text as a `title` (one line in `pages/chat/directory.tsx`).
- **VI-17, VI-31** bitop-ui `Table` `stack`: below 600 px each row is a block, the first cell on its own line and the others under it with their column names. Used by notification settings, platform limits, a team's limits and Costs → Prices.
- **VI-18** Connected apps has its own breadcrumb (not "Home"); its card is "Your apps" under the page title.
- **VI-19** bitop-ui `Popover` `pointerFocus="popup"`: the bell's popover focuses itself when a mouse opens it (the keyboard still lands on the first notification).
- **VI-28** The pattern was bitop-ui `Card`'s actions refusing to shrink: they now wrap within the card when they sit under the title, so a status line can't widen the page.
- **VI-29** bitop-ui `Table` centres `empty` content on the visible width of its scroll box (sticky, `100cqi`).
- **VI-30** A joined `ToggleGroup` (segmented filters, date presets) and pill `TabsList` wrap onto more lines when they don't fit, so no choice is cut off (`overflow="scroll"` keeps the old fading strip). Decision: wrapping shows every choice on a phone, which a fade alone didn't make obvious.
- **VI-35** Not a bug: the focused `SPAN` is Base UI's radio (`role="radio"`), the selected source type, which is where focus belongs in a choice dialog.
- **VI-36** Add connection's Name spans the form like Base URL and API key.
- **VI-37** The development sign-in list shows the personas' current names and emails from the database, and dev sign-in keeps a renamed persona's name and email instead of resetting them (new sqlc query `ListIssuerUsers`, no migration).

Leftovers from other milestones, done here:
