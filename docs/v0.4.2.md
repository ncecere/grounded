# v0.4.2: ready for a wider beta

Status: **being built** (owner, 2026-10-04). A patch release that fixes everything a pre-beta bug hunt found in [v0.4.1](releases/v0.4.1.md), before a larger beta.

## Scope (owner, 2026-10-04)

Four testers used v0.4.1 by role on a copy of the reference data (platform admin and auditor; a team owner and editor building an assistant; members, signed-out visitors, phones and keyboard; a visual sweep of every page at five widths) and filed 119 findings; the owner added two. After merging duplicates: 0 P0, 9 P1, 24 P2, about 70 P3. **All of them are in v0.4.2** (owner: nothing has been widely released yet). axe found no violations on any page tested.

The findings, with steps and screenshots, were kept with the test run; each is summarised in the milestone that fixes it below, under its tester ID (AD admin, BU builder, US users, VI visual, OW owner).

## Owner decisions

- **Scope:** every finding, P1 to P3 (2026-10-04).
- **OW-2, a Reranking page (option A):** reranking gets its own page, **Admin → Models → Reranking**, always in the sidebar like SystemOne: its status (on/off, model and health, candidates, time limit, agents that turned it off), a setup guide when nothing is set up (a connection that serves `/rerank` → a model of kind Rerank → choose it, with a button for each step and which are done), the settings (moved here from the Models page's dialog), a test with a sample query, and "Reranking: off · Set up" / "on · <model>" in Admin → Overview → Features. Before, its settings appeared only as a notice on Admin → Models once a rerank model existed, so nothing said reranking existed.

- **VI-38, dark mode (option A):** the app follows the system's light or dark setting, with **System / Light / Dark** in the person's settings; the existing dark theme is checked page by page first (a visual pass in dark mode), and if that finds too much, dark mode waits until after the beta (owner, 2026-10-04). Built as **M6** after M5 (the same shell files).

## As built: M2

The agent pages and the New agent dialog. One finding per bullet; decisions where the design was silent are marked **Decision**.

- **OW-1 (BU-01, VI-01), the Build tab scrolled past its content.** Two causes, both fixed. The split's height is measured from its own top to the window's bottom (`build/fill-height.ts`: a `ResizeObserver` on its ancestors and the window's resize), less a 1.5rem gap, and it pulls in main's 5rem bottom padding with a negative margin (the 34 px every page had); at least 20rem, so a very short window scrolls the page as it must; below 1100 px the sections stack as before. Both panes are `position: relative` (the SystemOne checks legend's `.sr-only`, and the Instructions label's, now lay out and clip inside the pane instead of stretching the document) and `overscroll-behavior: contain`. I checked every absolutely positioned element inside the panes: the e2e test fails if any is laid out against something outside its pane. The fixed formula is only the first paint's fallback. **Decision:** measuring in app code rather than a flex column from `main` down, because that chain runs through the shell and the DetailPage template (M5's). e2e `agent-editor.e2e.ts`: at 1711x1295, 1440x900 and 1280x720, opening every section bottom up with the pane scrolled to the top before each, then top down, CDP wheel events inside the pane past its end and over the header, PageDown, End and Space, then closing them all: `scrollHeight ≤ innerHeight`, `scrollY` 0, nothing escaped; a "Fix these before publishing" alert shrinks the split instead. Without the `position: relative` the test fails.
- **BU-03, Share stale after publishing.** Taking a newer server copy (publish, revert, status change) also refetches the sharing view. "All three work without signing in" says "Both" when there's no short address.
- **BU-05, "Unsaved changes" stuck.** The draft's saved-or-not check compared JSON with key order; the server returns SystemOne overrides in its own order. It now compares with sorted keys (`conflict.ts` `same`, also used by the conflict helpers).
- **BU-06, the Safety table cut off.** The section's grid has a `minmax(0, 1fr)` column, so the category table scrolls in its own box and the text wraps.
- **BU-07, Tools.** Tools with the same name name their server in the label ("…, from Service status"); a tool whose server's latest health check failed says so in its description. API (additive): `serverHealth` on `MCPToolOption`.
- **BU-09, editors and a public agent's live profile.** Enforced server-side: while the agent's live audience is beyond the team, only team admins and owners change its name, address, description, accent, welcome or starters (403 `live_profile_forbidden`; the same values and the draft are fine).
