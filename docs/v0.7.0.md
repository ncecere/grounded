## Decisions

### Configuration as code

- **How it's applied (option A):** in the UI and through the API. A team's Settings gets **Export configuration** (YAML) and **Import configuration**, which shows a dry-run diff ("2 agents changed, 1 source added") before applying; the same export, dry run and apply are API endpoints a pipeline can call with an API key.
- **What's in a file:** names, settings, instructions, agent versions and references (a source's URL or crawl rules, a knowledge base's sources, webhooks). Never uploaded files, passages, conversations or secrets: keys stay in the target install and are referred to by name.
- **CLI and SDKs (owner):** a command-line tool may come back later (it would call the same endpoints); **no SDKs**.

### Model cards and the accessibility statement

- **Model cards (option A):** an **About this assistant** card per agent, generated from its settings so it can't drift: the model, the sources and when they were last updated, what's checked (passage judging, claim checks, moderation), the audience, data handling (how long conversations are kept, who can see them, whether questions may be shared) and its limits ("answers only from these sources; may be wrong; check the cited page"). The team may add a short note (ownership, contact). Shown from an ⓘ in the chat header and on the public page and widget.
- **Accessibility statement:** one platform page: the WCAG 2.1 AA target and how it's tested (axe in every build, keyboard and screen-reader checks), known limitations, and a contact for reporting problems; platform admins edit the contact and may link their institution's own statement.
