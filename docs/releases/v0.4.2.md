# Grounded v0.4.2

v0.4.2 gets Grounded ready for a wider beta. Four testers used v0.4.1 by role on a copy of the reference data — a platform admin and auditor, a team owner and editor building an assistant, members and signed-out visitors on phones and with a keyboard, and a visual sweep of every page at five widths — and filed 119 findings; a second round re-tested the fixes and found 63 more. All of them are fixed here, along with three things the owner asked for: a **Reranking** page, an **Admin Settings** page and **dark mode**. The scope and decisions are in [`v0.4.2.md`](../v0.4.2.md); the full list is in the [changelog](../../CHANGELOG.md).

## Highlights

- **Admin → Models → Reranking** ([`operations/rerank.md`](../operations/rerank.md)). Reranking has its own page, always in the sidebar like SystemOne: whether it's on and with which model (and its health), a setup guide while nothing is set up (a connection that serves `/rerank` → a model of kind Rerank → choose it), the settings, a before-and-after test on a knowledge base, and the agents that turned it off. Admin → Overview shows "Reranking: off · Set up" or the model in use. Before, its settings appeared only once a rerank model existed, so nothing said reranking was there.
- **Admin → Settings** ([`operations/settings.md`](../operations/settings.md)). The platform's general settings in one place: the time zone (which also sets the date agents are told), the currency and default monthly budget, the feature switches, and the values set by environment variables, read-only. Costs → Settings keeps the cost tracking mode and warning threshold; Overview keeps each feature's status with a link.
- **Dark mode** ([`personal-settings.md`](../personal-settings.md)). Grounded follows the device's light or dark setting; the account menu's **Theme** sets System, Light or Dark. The public page and the widget follow the visitor's device. Every page was checked in dark, by every role, at desktop and phone sizes.
- **Answers you can rely on with tools.** In tool mode the answer is the model's final turn: what it wrote before calling a tool is no longer shown or stored (a reader who saw some of it has it cleared). Results of tools the model called are no longer judged out by SystemOne. A follow-up's rewritten search query is checked before use, and the original question is searched when the rewrite doesn't read as a query. Reasoning a model writes into its answer (`<think>…</think>`) is treated as reasoning. A low-confidence "contradicts" shows as "not supported".
- **Your work is kept.** A save conflict (someone saved first) keeps what you typed on every settings form, lists what changed, and offers **Overwrite with mine** or **Discard mine and load theirs**. A new widget key's one-time secret can no longer be hidden by a false "Leave without saving?". Bulk delete acts on exactly the documents it names.
- **Phones, tablets and keyboards.** The agent Build tab no longer scrolls past its content at any size; tables, filters, tabs and breadcrumbs fit on a phone; below 1100 px the sidebar starts as icons; a new chat focuses the message box, two Tabs away with a skip link.
- **Hundreds of smaller fixes**: a chat link to a deleted conversation shows "This conversation isn't available" instead of retrying until you're rate-limited; a rate limit shows a countdown and **Try again now** instead of a blank error; stable citation numbers, matching Copy and Export; Stop with **Ask again**; follow-up chips that are real questions; New agent starts on a healthy chat model; failing models and MCP tools are marked; editors can't change a live public agent's public face; validation for OCR languages, currencies and the crawl allowlist (private and metadata addresses are refused); budget extensions can be revoked; unused classification levels can be deleted; ⌘K finds settings by several words.

## Upgrading from v0.4.1

A rolling upgrade with no downtime. Take a backup as for any upgrade ([`operations/upgrades.md`](../operations/upgrades.md)), then change every `?ref=v0.4.1` in your overlay to `?ref=v0.4.2` and pin the new digests of `ghcr.io/ncecere/grounded` and, if you run OCR, `ghcr.io/ncecere/grounded-ocr`.

**No migrations** (the schema stays at version 44) and **no new environment variables**.

Things people will notice:
- **Dark mode** on devices set to dark. Anyone who prefers light chooses it under the account menu's Theme.
- **New admin pages:** Admin → Models → Reranking and Admin → Settings; the time zone, currency and default budget moved from Costs → Settings, and the feature switches from Overview.
- **Editors** can no longer change the name, address, description, look, welcome message or starter questions of an agent that's live for signed-in users or the public; team admins and owners can (editors still edit the draft).
- **The crawl allowlist** refuses private, loopback, link-local and metadata addresses (the crawler never fetched them) and asks before saving `*`.
- **Tool-mode agents** stream only their final turn; on the OpenAI-compatible endpoint, agents with tools send their answer at the end instead of streaming it, because that protocol can't take text back.
- **API** (additive): a `text_reset` chat event, `title` on tool calls, `tz` on exports, `none` as a feedback rating (take a rating back), health on chat models and MCP tools, `GET /v1/admin/features`, revoking a budget extension. Generated Go clients: `apitypes.Up`/`Down` are now `FeedbackRatingUp`/`FeedbackRatingDown`.

## Known limitations

The [v0.4.1 limitations](v0.4.1.md#known-limitations) still apply, and:
- **The theme** is kept per browser, not per account.
- **Follow-up chips** after a reload are remembered by the browser tab, not stored with the conversation.
- **A stopped answer** can store a token that was on its way to the browser when Stop was pressed.
- **Partly scanned PDFs** processed before v0.4.1 still need to be uploaded again to have their scanned pages read.
