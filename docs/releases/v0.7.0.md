# Grounded v0.7.0

**Better knowledge in, continued.** Six opt-in changes to what is indexed and how,
each judged with the index preview before anything switches. **Every one is off
by default**, and an install that turns nothing on indexes, retrieves and answers
exactly as v0.6.3 did. None has been measured on a real knowledge base with a real
embedding model: the release does not say retrieval improves. Try each with
**Preview new settings** on your own knowledge base and decide by the comparison.

The planned "adoption by other installs" release (Helm chart, configuration as
code, the docs site and registry, the accessibility statement and model cards) is
now **v0.8.0**, and identity and compliance is v0.9.0. Their scope is unchanged
([`roadmap.md`](../roadmap.md) § L).

## What's new

- **Near-duplicate repeated blocks** (#23). With `boilerplate.fuzzy` on for a
  source, menus and footers that differ by a highlighted item or a date are
  recognised as one repeated block instead of being kept on every page. Bounded
  MinHash matching; exact matching is byte-for-byte unchanged when it is off.
- **Tables kept structured: chunker version 3** (#24). A table that fits is kept
  whole; a longer one is cut between rows and every piece repeats its caption and
  header row. Merged table cells now keep their columns in HTML and DOCX parsing
  for every chunker version (this changes the parsed text of such tables).
- **Structural boundaries: chunker version 4** (#19, first part). For sections
  that mix several procedures: no merging across a heading of any level, and a
  standalone bold label directly above a list starts a new passage. It reads
  formatting, not meaning. #19 stays open for a measurement on real pages.
- **Parent/child retrieval** (#20). A profile can set **Parent sections**: search
  still ranks small passages, but the agent's model is given the section around
  each match. Citations keep pointing at the matched passage.
  `RETRIEVAL_PARENT_EXPANSION=false` turns it off without re-indexing.
- **Content health report** (#22). Editors can ask for a bounded, read-only report
  of documents not processed recently, links the latest crawl saw fail,
  byte-identical files in two sources, documents with no retained citation
  evidence, and documents that failed to parse. Off until a platform admin turns
  it on; it fetches nothing and calls no model.
- **Contextual chunks** (#21). For a source that opts in, a chat model writes a
  short description of where each section sits in its document, and that text is
  put in front of the passage **only in what is embedded**: passages, keyword
  search, citations and viewers are unchanged. Platform and source switches are
  off by default; a platform admin sets explicit per-build and per-day call, token
  and configured-price limits; estimates make no model call; activation is a held
  index preview with an explicit switch. Configured prices are local accounting,
  not a provider invoice. Two bounded real-model checks passed the mechanics and
  showed no improvement on a tiny synthetic set
  ([details](../benchmarks/contextual-chunks.md)).

The [CHANGELOG](../../CHANGELOG.md#070---2026-11-01) has the full entries,

## Database and upgrade

Schema **59**, up from 55 in v0.6.3. All four migrations only add:

- **00056** (fuzzy boilerplate): the per-block MinHash sketch storage and the
  source setting, default off.
- **00057** (parent/child): `embedding_profiles.parent_tokens` (default 0, off)
  and nullable passage parent ranges.
- **00058** (content health): new tables only.
- **00059** (contextual chunks): `embedding_profiles.contextual` (default false)
  and new settings, cache and accounting tables.

Old and new code run together on schema 59 while the new features stay unused:
the upgrade rehearsal from v0.6.3 passed old/new reads and writes. **Upgrade every
API and worker before turning on any new feature**: older binaries cannot build
chunker v3/v4, parent-section or contextual indexes. Before rolling back to an
older image, switch affected knowledge bases back to their previous (plain)
indexes; a kill switch alone does not rewrite vectors. Follow the
[upgrade guide](../operations/upgrades.md), verify a backup, and pin **both** the
application and OCR images to the published digests.

## Known limitations

- **No quality measurement.** Every feature here was validated with fake models,
  test sites and, for contextual chunks, two small synthetic real-model checks.
  Reranking on/off and per-step latency on a reference install (#25) are still to
  do.
- **Chunker v4 reads formatting.** Procedure changes without a heading or bold
  label are not detected, and a misleading bold line makes an extra passage.
- **Contextual chunks spend money.** Limits are enforced on locally counted
  tokens and configured prices; unknown usage keeps its reservation. Nothing here
  verifies a provider invoice.
- Existing limitations in [v0.6.1](v0.6.1.md#known-limitations) remain unless a
  change above explicitly resolves them. This is a pre-1.0 release, not a v1.0
  readiness declaration, and no production deployment is part of it.
