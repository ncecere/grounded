# Grounded v0.8.0

**Adoption by other installs, first part.** A Helm chart for installs that don't use Kustomize, an accessibility
statement and an "About this assistant" card on every chat surface, and a polish pass over the whole interface.
An install that changes nothing keeps working exactly as v0.7.0 did: the chart is an alternative to Kustomize, not a
replacement, and the new card and statement need no configuration.

Configuration as code (D4) and the bitop-ui docs site and registry (F11), planned for this release, move to
**v0.9.0** with identity and compliance. Import needs decisions first
([design for review in #214](https://github.com/ncecere/grounded/pull/214)), and shipping what is ready now was better
than holding it ([`roadmap.md`](../roadmap.md) § L).

## What's new

- **Helm chart** (F5, #31). `deploy/helm/grounded`, generated from the Kustomize base by a script and checked in CI
  against an independent Kustomize render, so the two can't drift. Bounded values: external or bundled Postgres and
  Valkey, replicas, OCR, ingress, tracing and monitoring, existing Secret names, and a digest-pinned image. An
  external datastore names exactly where it is (a namespace and pod labels, or one `/32` address), and the network
  policy allows only that. Each release from this one publishes a signed OCI chart pinned to its images. A
  [lifecycle script](../../deploy/helm/scripts/kind-lifecycle.sh) exercises install, upgrade, rollback, a negative
  network-policy control and uninstall on a throwaway kind cluster. Start with
  [`deploy/helm/README.md`](../../deploy/helm/README.md).
- **About this assistant** (E8, #34). An ⓘ beside every agent's name, in signed-in chat, on the public page and in the
  widget, describes it from its published settings: the model (a generic label), who it is for, how many sources and
  when they were last processed, which checks are configured, how long conversations are kept, its limits, and an
  optional **ownership note** the team writes in Build → Instructions (published with the agent, never before). It
  never names sources and never calls a model to build the card.
- **Accessibility statement** at `/accessibility`: the WCAG 2.1 AA target and how Grounded is tested, its known
  limits, and where to report a problem. Platform admins set the reporting contact and can link their institution's
  own statement.
- **A calmer interface.** One radius rule; lighter control borders that still meet contrast requirements; one focus
  ring; every filter bar's toggle group drawn as a segmented track; a cleaner active item in the sidebar; flat cards;
  no card inside a card on Home; each agent's own avatar in the Agents table; and several small fixes. Nothing about
  how a page works changed. Before-and-after screenshots are in #213.

Also fixed: a source's **Repeated blocks** list could show different sample text depending on the order its pages
were uploaded (#215); what is indexed was never affected.

The [CHANGELOG](../../CHANGELOG.md#080---2026-11-04) has the full entries.

## Database and upgrade

Schema **60**, up from 59. Migration **00060** only creates the accessibility statement's settings table; old and new
code run together on schema 60. The ownership note is stored in agent configuration only when set, so configurations
without one are byte for byte as before. During a rolling upgrade, saving a note through an API still on v0.7.0 is
refused (the editor keeps the text; save again when the rollout is done). Every other save works. Follow the
[upgrade guide](../operations/upgrades.md), verify a backup, and pin **both** the application and OCR images to the
published digests. With Helm, use the chart version that matches the release.

## Known limitations

- **The Helm chart is new.** Its lifecycle was exercised on kind with v0.7.0 images and fixtures, not on a production
  cluster, and a previous-release SQL upgrade through Helm has not been run. Kustomize remains the reference.
  Anything outside the bounded values (backups, CloudNativePG, private registries, unusual routing) stays
  Kustomize-only.
- **The accessibility statement states a target.** Automated axe checks and keyboard tests run on every release;
  Grounded has not had an independent screen-reader audit.
- **On phones, wide tables** keep their row actions pinned over the next column while you scroll sideways.
- Existing limitations in [v0.7.0](v0.7.0.md#known-limitations) remain unless a change above resolves them. This is
  a pre-1.0 release, not a v1.0 readiness declaration, and no production deployment is part of it.
