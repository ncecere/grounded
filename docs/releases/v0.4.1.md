# Grounded v0.4.1

v0.4.1 is a patch release of small wins after [v0.4.0](v0.4.0.md): follow-up questions after an answer, evaluation questions that can't pass flagged before you run them, OCR for every page of a TIFF and for partly scanned PDFs, SystemOne capacity that keeps answers first, and reasoning shown in the order it happened. The design and the owner's decisions are in [`v0.4.1.md`](../v0.4.1.md); the full list is in the [changelog](../../CHANGELOG.md).

Every feature was checked by hand on the reference data before the tag (the signed-in chat, the public page and widget on a phone, evaluations, OCR with real files, the agent editor), and the problems found were fixed.

## Highlights

- **Follow-up suggestions** ([`follow-ups.md`](../follow-ups.md)). After an answer with citations, up to 3 follow-up questions appear under it as chips, in the chat, on the public page, in the widget and in Try it; choosing one asks it. They come from a separate, small call to the agent's chat model after the answer has ended, so nobody waits for them and the answer and its checks are untouched; each must be answered by one of the passages the answer found. They're moderated like answers, saved and replayed with saved answers, and metered as `suggestions` in Costs. On for every agent; **Build → Advanced → Suggest follow-up questions** turns them off.
- **Evaluation questions that need attention** ([`operations/evaluations.md`](../operations/evaluations.md#building-a-set)). A set's page checks every question against the knowledge base: an expected document nothing matches (or one deleted), a must-mention phrase no source contains, or an expected page that wasn't in the top 50 results in each of its last 3 retrieval runs ("out of reach"). The header says "3 questions need attention", the Questions tab has a filter, and **Run** says how many questions can't pass without blocking the run.
- **OCR follow-ups** ([`ocr.md`](../ocr.md)). Every page of a multi-page TIFF is read. A PDF indexed while OCR was off with some scanned pages stays **Ready**, is listed under **Needs OCR**, and **Retry with OCR** (or **Retry all that need OCR**) reads just those pages once OCR is on. The cluster smoke test now runs the OCR sidecar.
- **SystemOne capacity: answers first** ([`systemone.md` §8](../systemone.md#8-capacity)). When every slot of a SystemOne connection is busy, a freed slot goes to a check an answer is waiting for before background work (evaluation runs, the gap topics job), and background work may hold at most half the slots, whatever the configured limit. Below the limit nothing changes. A new metric, `grounded_systemone_wait_seconds`, shows when the limit is too low; the docs give sizing advice for large installs. Each SystemOne check in the agent editor shows the time it adds ("Adds about 0.7 s per answer").
- **Reasoning and tool steps in order.** For agents in tool mode and with MCP tools, the agent editor's Try it shows the reasoning before a tool call, the call, then the reasoning after it, instead of every tool first and all the reasoning merged after them; stored conversations too.

Fixes: today's date in answers is the platform's (the time zone in Admin → Costs → Settings), not UTC: in the evening in the Americas, agents said it was already tomorrow. A reloaded refusal offers the starter questions again. See the changelog for the rest.

## Upgrading from v0.4.0

A rolling upgrade with no downtime. Take a backup as for any upgrade ([`operations/upgrades.md`](../operations/upgrades.md)), then change every `?ref=v0.4.0` in your overlay to `?ref=v0.4.1` and pin the new digests of `ghcr.io/ncecere/grounded` and, if you run OCR, `ghcr.io/ncecere/grounded-ocr`. Refresh the dashboards and alert rules from `deploy/observability` (a SystemOne wait panel on Models and moderation).

**No migrations** (the schema stays at version 44) and **no new environment variables**.

Things people will notice:
- **Follow-up chips** under answers with citations, a few seconds after the answer ends. Each costs one small chat call; on a reasoning chat model, set **How to turn thinking off** (Admin → Models → Compatibility) so the call is quick, or it may time out (10 s) and show none.
- **Evaluation sets** may show questions that need attention right away: they're checked against the knowledge base as it is today.
- **Partly scanned PDFs** uploaded from v0.4.1 on join **Needs OCR**; ones processed before keep their old warning (delete and upload them again to have their scanned pages read).
- **"Today"** follows the platform time zone. Saved answers to questions about relative dates change key at the platform's midnight instead of UTC's.
- **API** (additive): a `suggestions` chat event, `citationsPending` on `message_end`, `followUpSuggestions` on agent config, `thinkingBefore` on stored tool calls, `refused` on conversation messages, a set's problems (`GET /v1/teams/{team}/evaluation-sets/{setId}/problems`), and `latencyP50Ms` per feature on SystemOne status.

## Known limitations

The [v0.4.0 limitations](v0.4.0.md#known-limitations) still apply. For the new features:
- **Follow-up suggestions** aren't kept with stored conversations (a reloaded conversation shows no chips), and aren't offered on the OpenAI-compatible endpoint, MCP `ask`, JSON replies or evaluation runs.
- **Out of reach** counts retrieval runs only (full-answer runs don't search 50 deep).
- **The SystemOne limit is per process:** each API and worker pod has its own slots. A limit shared across the cluster is a possible follow-up.
