# Grounded v0.11.0

**The connector framework, and the hardening pass's follow-ups.** v0.11.0 makes source types a registry and adds the
framework every connector is built on: encrypted credentials, scheduled and incremental syncs, a hold on large removals,
and permissions from the provider. No connector ships in it yet. It also finishes the work the v0.10.0 hardening pass
left open: storing a document no longer slows down as a team grows, ingestion stops redoing finished work, answers
start sooner, public pages load less, and the code is easier to work on.

An install that changes nothing keeps working as v0.10.0 did, only faster. **Connector types are off** until a platform
admin turns one on, and none exists yet.

The SharePoint, OneDrive and Google Drive connectors planned for this release move to v0.12.0.

Published **(pending)** at source **(pending)**. The [validation record](../security/validation/v0.11.0.md) lists the
exact sources, checks and their limits; the published-artifact verification follows after the tag.

## What's new

- **Source types are a registry** (#258, [ADR-0035](../adr/0035-source-type-registry-and-connectors.md)). Upload and
  web are its first two types and work exactly as before. `GET /v1/source-types` lists the types an install has and
  what each can do. A platform admin can turn a type off (**Admin → Settings → Features → Source types**): no new
  source of that type can be created, and existing sources and their documents stay.
- **The connector framework** (#258, [guide](../source-types.md)). A connector source:
  - keeps its credentials encrypted and never shows them;
  - syncs on request or on a schedule (hourly, daily, weekly), reads only what changed, and removes what its provider
    no longer has;
  - **removes nothing when a sync would empty it or remove more than 30% of it** (`CONNECTOR_REMOVAL_HOLD_PERCENT`),
    and waits for an editor to confirm or dismiss: a revoked permission or an outage can look like "everything was
    deleted";
  - restricts each document to the people and groups its provider names when the connector reports permissions, and
    gives nobody access to anything it can't express.

  In the app, **New data source** offers the connector types that are on, with a form built from the type's settings
  and a **Test connection** button; a connector source has a **Syncs** tab, **Sync now** and **Sync everything**.

## Faster

- **Storing a document no longer slows down as a team grows** (#249, [ADR-0036](../adr/0036-document-counters.md)).
  The document and storage limits, the source pages, the documents table's tag filter and the admin team pages read
  counters instead of counting every document. With a million documents in one team, storing a document took 95 ms
  and takes 6.5 ms, and the source page's statistics took 825 ms and take 1.3 ms. Triggers on `documents` keep the
  counters, so every write is counted, including the previous release's during a rolling update; a daily job checks
  them and corrects any difference with a warning in the log, and `grounded doctor` checks the triggers.
- **Ingestion stops redoing finished work** (#250).
  - A changed document embeds only its changed passages: a one-byte change in a document of 1,100 passages embeds 1
    instead of 1,100. Unchanged passages keep their IDs, so citations to them still resolve.
  - A retry after an embedding outage or a limit wait starts from chunking: the original is not read again and
    **scanned pages are not read or counted with OCR a second time** (they used to count against
    `ocr_pages_per_day` again).
  - The boilerplate refresh works on 8 documents at a time (39 documents in 2.4 s instead of 14.8 s in the test), and
    contextual chunks describe a document's sections several at once, with the same result.
  - An unchanged web page's links are followed without reading the page back from object storage on every sync.
- **Less waiting before the first token** (#251). The reads a question makes before the model starts run together
  instead of one after another, and the settings every question reads are kept for 5 seconds per process. A signed-in
  follow-up makes 44 database round trips instead of 51, a public question 44 instead of 52. On MCP, a tool call reads
  only its own tool's list, and an agent's calls to an MCP server reuse one connection instead of a new handshake each.
- **Public pages load less** (#252). The widget, shared conversations and public agent pages no longer download the
  signed-in app's sidebar, search and notifications: the entry script is half the size (40.5 kB to 19.9 kB
  compressed). Pointing at a link to an agent, a source or a knowledge base starts loading its data with the page.

## Changed behaviour

- **Settings take up to 5 seconds to reach the other servers.** A change applies at once on the server that made it
  and within 5 seconds on the others: disabling a model or a connection, rotating a connection's key, lowering a
  rerank or SystemOne model's classification ceiling, turning public agents off. **Moderation policies are still read
  on every question**, so a tightened policy applies to the next question everywhere.
- **Text and Markdown files are capped at 32 MiB of text**, as the converted text of every other format already was. A
  larger file fails as `too_large` instead of becoming tens of thousands of passages.
- **The API's source `type` is an open string** instead of the list `upload`, `web`. Clients that send or compare
  `upload` and `web` are unaffected; a generated client loses the two-value enum.
- **One message for a bad `limit`.** Every list that takes `?limit=` answers a value out of range with
  `400 invalid_limit` and "limit must be between 1 and N". The ranges are unchanged.
- Retention removes the stored files of deleted content after its database transaction instead of inside it, and
  retries any that fail on its next run.

## Fixed

- **A streaming answer could be cut off and replaced** when the open conversation was read again in the background,
  after the network came back for example.
- **Long text could be cut inside a character.** Several places shortened text by bytes, so a name, title or message
  with accented or non-Latin letters could end in a broken character (connector titles, web source errors, audit-stream
  fields and others).
- A knowledge base's index-migration notice and index preview, and a source's access groups, were not refreshed with
  the rest of a team's pages.
- Two chat panels on one page gave their character counters the same id.

## Security

## Database and upgrade

Schema **74**, up from 69. All five migrations are expand-only, and old and new code run together on schema 74; the
`upgrade` job checks that the v0.10.0 image still serves the migrated schema.

- **00070** (source types) replaces the lists of types with a format check. It runs outside a transaction: each check
  is added `NOT VALID` and validated in its own statement, so the scan does not block writes. It changes no row.
- **00071** (connectors) adds three tables and two columns on `documents` (with constant defaults, so no rewrite). It
  changes no existing row.
- **00072** (document counters) adds three tables, three statement-level triggers on `documents` and a reconcile
  function. Adding the triggers takes a brief lock on `documents`.
- **00073** fills the counters from the existing documents, outside a transaction, one statement per counter, while
  writes go on. It reads every document once per statement: 0.5 to 2 seconds each with a million documents. Running it
  again adds nothing.
- **00074** adds the table `web_page_links`.

New settings, both with defaults: `CONNECTOR_CONCURRENCY` (2) and `CONNECTOR_REMOVAL_HOLD_PERCENT` (30). Follow the
[upgrade guide](../operations/upgrades.md), verify a backup, and pin **both** the application and OCR images to the
published digests. With Helm, use the chart version that matches the release. **Turn on a connector type only after
every pod runs v0.11.0.** There is none to turn on yet.

## Known limitations

- **No connector ships in this release.** SharePoint (#259), OneDrive (#260) and Google Drive (#261) are next, in
  v0.12.0; they need test tenants. What the framework leaves for later is #280, including how a platform admin allows
  a self-hosted service on a private address.
- **A document indexed before the upgrade is embedded whole the first time it changes**, and only its changed passages
  from then on. With contextual chunks every passage is still embedded again when a document changes.
- **The 5-second settings cache** means a server can use a setting up to 5 seconds old after a change made through
  another server.
- **The full-text search still ranks every matching passage** before it keeps the best (#251, item 6). Bounding it
  changes ranking and needs evaluation sets on a real knowledge base (#89).
- The performance numbers above were measured on a development machine with the fake model gateway and seeded data,
  not on a production install under load. Capacity at the design's size is still issue #89.
