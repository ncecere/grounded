# Grounded v0.9.0

**Identity and compliance.** v0.9.0 covers the questions an institution's security and compliance review asks before a wide rollout: who gets
access, what is logged and where it goes, what sensitive data is indexed, and what each agent may spend. It also brings
configuration as code and the published bitop-ui registry, both carried over from v0.8.0.

An install that changes nothing keeps working as v0.8.0 did, with one exception: **personal data scanning is on by default**.
It only flags documents; nothing is held back until a platform admin chooses classification levels to hold. Everything
else (SCIM, streaming, signed exports, per-agent budgets) stays off until someone sets it up.

Published **pending** at source `pending`. The [validation record](../security/validation/v0.9.0.md) lists the exact
sources, checks, published-artifact verification and their limits.

## What's new

- **SCIM provisioning** (E4, #35). Your identity provider (Entra ID, Okta, authentik, or any SCIM 2.0 client) can:
  - create people before their first sign-in and keep their names and email addresses current;
  - **suspend people who leave**: their sessions end at once, and their API keys, connected apps and MCP tokens stop
    working. A DELETE suspends and unlinks; it never deletes the person.
  - **feed SSO group → team rules** with its groups, so team membership is decided in one place.

  A provisioned person is linked at first sign-in by the identity provider's object ID (`SCIM_MATCH_CLAIM`: `sub` by
  default, `oid` for Entra ID), **never by email**. The last active platform admin is never suspended. Tokens are
  managed in **Admin → SCIM provisioning**. Tested end to end against authentik 2025.10.
  [Runbook](../operations/scim.md), [design](../specs/scim/DESIGN.md).
- **Audit streaming to a SIEM** (E5, #36). A platform admin can send every new audit entry, within seconds, in commit
  order, to up to five destinations:
  - Splunk HEC;
  - NDJSON over HTTPS (Elastic Agent, Logstash, Vector, Fluent Bit);
  - syslog over TLS (RFC 5424 and 5425).

  Only the audit facts are sent: never before and after values, metadata or content. To start, turn on **Audit
  streaming** in Admin → Settings → Features, then add destinations in **Admin → Logs → Streaming**.
  [Runbook](../operations/audit-streaming.md), [design](../specs/audit-streaming/DESIGN.md).
- **Signed daily audit exports** (E5, #36; [ADR-0034](../adr/0034-signed-daily-audit-exports.md), now Accepted). Each
  closed UTC day's audit facts are exported as a hash-chained JSONL file with an Ed25519-signed manifest, which can be
  checked offline with OpenSSL. Optionally, each day is **copied to an S3 bucket outside Grounded**, preferably with
  Object Lock (`AUDIT_EXPORT_COPY_S3_*`); every copy is checked against its signature and read back.
  [Design and verification](../signed-daily-audit-export.md).
- **Personal data scanning at ingest** (B7, #37). Each document is checked for:
  - US Social Security numbers;
  - payment card numbers that pass the Luhn check;
  - up to 20 patterns the institution adds.

  Flagged documents show **Needs review** and appear under Needs attention and in content health. Editors dismiss the
  flag or delete the document. Platform admins can choose classification levels to **hold**: such documents stay out of
  search until approved. Matched text is never stored, logged or shown. [docs/pii-scanning.md](../pii-scanning.md).
- **Per-agent budgets** (E17, #38). Team owners and admins can give each agent its own monthly budget. When the team's
  budget is enforced, an agent over its own budget is refused while the team's other agents keep working. When the
  team's whole budget is used up, queued documents and profile-migration re-embedding now wait, instead of finishing
  over budget. [Design](../specs/agent-budgets/DESIGN.md).
- **Configuration as code** (D4, #32; [ADR-0033](../adr/0033-team-configuration-as-code.md)). A team's sources,
  knowledge bases, agents, evaluation sets and webhooks can be exported as YAML. Before an import, Grounded shows every
  change. Applying is all or nothing, never deletes, and starts no crawl, run or model call.
  [Design](../specs/config-as-code-import/DESIGN.md).
- **Usage by where it was used** (E13, #39). Admin → Analytics splits tokens by channel: the app, the public page, the
  widget, the APIs, MCP, tests, evaluations and background work.
- **Auditors see admin team settings** as read-only facts (E16, #40).
- **bitop-ui is published** (F11, #33): its docs site and component registry are at
  https://ncecere.github.io/bitop-ui/, and Grounded installs its UI components from there.
- **Pill tabs** on every admin page with several sections. New: Settings, Parsing & OCR, Logs (Audit, Access, Signed
  exports, Streaming), Personal data and SCIM provisioning. Old `#section` links open the right tab.

Also fixed:

- **Boilerplate counts:** a source's repeated-block counts could miss documents from an upload batch that was still
  being indexed (#226).
- **Profile-migration preview:** the comparison could stay "running" when the database pool was small (#227).
- **Concurrent migrations:** two pods migrating a database at the same time could deadlock. Migrations now poll for
  their lock instead of blocking on it (#228).

The [CHANGELOG](../../CHANGELOG.md#090---2026-11-06) has the full entries.

## Database and upgrade

Schema **67**, up from 60. Migrations **00061 to 00067** are all expand-only: they add tables, columns, indexes, one
trigger, and a wider API-key scope constraint. Old and new code run together on schema 67; the `upgrade` job checks
that the v0.8.0 image still serves the migrated schema.

- **00061** widens the API-key scope constraint for `configuration:*`. **To downgrade**, first delete keys that have
  a configuration scope.
- **00066** (audit streaming) runs outside a transaction. It adds `audit_log.txid`, set by an insert trigger, and
  builds an index on it **concurrently**, so the audit log stays writable. A concurrent build waits for transactions
  that were open when it started. **During the upgrade, don't start pods from the previous release.** If the
  migration seems stuck, look for a long-open transaction in `pg_stat_activity` and end it, or delete the old pod.
  If an earlier attempt was interrupted, the migration drops the leftover invalid index and builds it again.

New settings, all optional:

| Setting | What it does |
|---|---|
| `SCIM_MATCH_CLAIM` | The sign-in claim matched to SCIM's `externalId`. Default `sub`; use `oid` for Entra ID. |
| `AUDIT_EXPORT_SIGNING_KEY_FILE` | Mounted file holding the Ed25519 signing key for the exports. Without it, nothing is exported. |
| `AUDIT_EXPORT_COPY_S3_*` | The bucket that receives the external copies. |

All three go in the runtime Secret or the ConfigMap. Follow the [upgrade guide](../operations/upgrades.md), verify a
backup, and pin **both** the application and OCR images to the published digests. With Helm, use the chart version
that matches the release.

## Known limitations

- **SCIM** was tested end to end with authentik only. Entra ID's and Okta's PATCH shapes are covered by tests built
  from their documentation, not by a live tenant.
- **Audit streaming** was tested against local HEC, NDJSON and syslog-over-TLS receivers, not a production Splunk or
  Elastic. Delivery is at least once (receivers can deduplicate on the entry ID). **A transaction left open anywhere
  on the Postgres server holds new entries back** until it ends. Nothing is lost or reordered, but the destination
  falls behind. A destination more than 15 minutes behind appears under Needs attention.
- **Personal data scanning** has built-in patterns for US identifiers only. Other countries' formats must be added as
  custom patterns. Detection uses patterns, not a model, so it misses free-text personal data.
- **With the Helm chart**, signed exports, and therefore their external copies, can't be turned on: the chart doesn't
  mount the signing key file. Use a Kustomize overlay. `SCIM_MATCH_CLAIM` and the copy bucket settings can go in the
  chart's runtime Secret.
- **Per-agent budgets** have no per-agent extension. A team extension raises the team limit only.
- Existing limitations in [v0.8.0](v0.8.0.md#known-limitations) remain unless a change above resolves them. This is
  a pre-1.0 release, not a declaration that v1.0 is ready, and no production deployment is part of it.
