# Grounded v0.6.1

v0.6.1 is a fix release. A QA pass of v0.6.0 (five testers working through chat, building agents and knowledge bases, the admin console, the API and security, and the five new features, about 600 checks) found real problems; this release fixes them. There are **no new features, no migrations and no new settings**: the schema stays at version 53 and the deployment manifests are unchanged. Several fixes **change what some people and integrations can do**, in the direction of the documentation, and those come first below.

## What changes for people and integrations

- **API keys reach only what they were given.** A key with only the **`mcp`** scope could read a team's sources, documents, knowledge bases and agents over the REST API; it now gets `403 missing_scope` there (it still works on `/mcp`). A key **restricted to knowledge bases** could read the sources and documents of the others; outside its knowledge bases a source does not exist for it, and it no longer lists or opens an agent that answers from any other. A key **restricted to agents** reaches only the knowledge bases those agents answer from (their published versions, as they are now), and with a knowledge-base restriction as well, only what both allow. A **personal key** never acts above its owner's current role: if they are made a plain member, its ingest scope stops working at once. (#110, #111, #112)
- **Members see an agent's published version, not its draft.** The agents list and an agent carried the draft (instructions, knowledge bases, settings, unpublished changes, publish problems) to every team member and to a member's query key. They now get the profile and the published version; editors, admins, owners and ingest keys are unchanged. (#129)
- **A shared link ends with its owner's standing.** It works only while the person who made it is an active user who may still chat with the agent, for everybody including them, and including a link open to anyone. If they leave the team, are suspended or lose access it stops, and it works again if they come back. Nothing is deleted. (#141)
- **Webhooks:** an update must say `url` and `enabled` (a missing one is named, `400 invalid_webhook`; a missing `events` is still `no_events`), and a description you do not mention is kept (a missing `enabled` used to switch the webhook off). An archived team's webhooks are read-only like its agents (`409 team_archived`). Deliveries waiting to retry when webhooks are switched off now wait and go on within five minutes of switching on again, instead of failing for good. People who cannot manage destinations no longer see the admin-only note. Sending the same rating again is not a new `feedback.submitted` event. (#134, #135, #137, #138, #139)
- **Team requests:** when a request names another person as owner, the approval notice says who owns the team and links to the requests page, and Request a team says "Owned by …" instead of offering an Open team link the asker cannot use. (#136)
- **Web sources:** a sync that fetched nothing says why ("Nothing was fetched: …"), a robots.txt that could not be reached is reported as that and not as the site forbidding crawling, and a source at an address the crawler never fetches (127.0.0.1, 10.x, 169.254.169.254, ::1) is refused as `blocked_address` instead of inviting a domain request that can never be approved. (#114)

## Fixed

- **API errors.** A NUL character (U+0000) in text is a clear `400 invalid_text`, not a 500 from about twenty endpoints (#109). A JSON body that does not fit names the field (`Unknown field "kbIds"`, `Field "limit" must be a whole number`); the code is still `invalid_json` (#115). The OpenAI-compatible endpoints answer a keyless request and an internal failure in OpenAI's error shape (#116). A JSON body has 30 seconds to arrive, then `408 request_timeout` and the connection closes; uploads are not covered (#118).
- **The web app.** A signed-out visitor on a team agent address no longer loops on "Loading…" at about 140 requests a second while public chat is off (#120); a session that ends while the app is open shows the sign-in page instead of "Something went wrong" (#121); citation markers after an unclosed backtick are recognised (#122); the source viewer's header stays in view, the chat's conversation list has Load more, the composer counts characters rather than UTF-16 units, a long question is cut short in the retrieval header, text from people is isolated so a right-to-left override cannot rearrange the words around it (#123–#127); a refused web-source save shows where you are looking, and the agent editor warns before losing a value held back as invalid (#130, #131). The audit and access log CSV exports neutralise spreadsheet formulas, a long unbroken name wraps instead of scrolling the page sideways, Open invites refreshes after Assign owner, and a refused sign-in no longer moves "Last sign-in" (#142–#145). Many smaller items from the polish lists (#128, #132, #140, #146, #119) are fixed too; each says which in its issue.
- **Documentation.** The API says members can read their team's document passages (behaviour unchanged, #113).

## Upgrading from v0.6.0

A rolling upgrade with no downtime and **nothing to migrate**: take a backup as for any upgrade ([`operations/upgrades.md`](../operations/upgrades.md)), change every `?ref=v0.6.0` in your overlay to `?ref=v0.6.1` and pin the new digests of `grounded` and `grounded-ocr` that the release's `*.digests.txt` list. No new environment variables.

Two things are worth a look afterwards, because they narrow access:

- **Keys restricted to agents** (Team settings → API keys). Each now reaches only its agents' knowledge bases. A key that was searching other knowledge bases of its team stops being able to; widen its agents or its knowledge bases if that was intended.
- **Shared links of people who have left or are suspended** stop working, by design.

**Rolling back** to v0.6.0 is safe: nothing in the database changed. The narrowing above is undone with the image.

## Known limitations

The [v0.6.0 limitations](v0.6.0.md#known-limitations) still apply, and:

- **Members can read the passages of their team's documents** (the data-source pages use them), up to 100 at a time; the whole text in order, and the chat's source viewer, are for editors, admins and owners. An API key with the query scope can read passages through that route even where a classification turns **direct retrieval off**, which is meant to stop programs reading content; closing that is a decision for the next release.
- **A shared link whose owner returns works again**, since a link is the owner's standing and nothing is deleted. Revoke a link to end it for good.
- **A crawl that fetched many pages and then stayed "Running"** for a long time, seen once during testing (165 pages fetched, then slow skipping), is not explained.
- **The layout fixes** were measured against a mock API and walked in one browser on the cluster, not on every browser.
- Some small items in the polish lists are still open: see the issues #119, #128, #132, #140 and #146.
