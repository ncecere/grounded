# Grounded v0.6.2

Status: **release candidate notes; not released**. The version is reserved for the
security fixes below, subject to all required CI, fresh vulnerability scans and
the upgrade check passing. No v0.6.2 tag has been cut.

## Security fixes

- **Go 1.26.10: GO-2026-6809 (`crypto/x509`).** Certificate verification rejects
  known intermediate certificates that are no longer trusted, including cases
  where a system trust store has not been updated. The previously pinned
  Go 1.26.9 is affected. The scanner reports a reachable verification path through
  an outbound MCP response body read.
- **golang.org/x/net v0.62.0: GO-2026-6860.** Avoids quadratic text-node coalescing
  while parsing HTML. Grounded's HTML ingestion reaches the affected parser
  through `htmlmd.Convert` and goquery; v0.61.0 is affected.

- **seroval 1.7.3 (shipped, through TanStack Router).** Fixes serialization
  injection advisories GHSA-f86p-h4j2-7qgj and GHSA-9wx9-5pv9-3349 present in the
  previous 1.6.9 lockfile entry. This is a preventative dependency update; the
  audit alone is not evidence of an exploitable Grounded feature.
- **undici 8.12.3 (development-only, through jsdom).** Fixes the HTTP/TLS and
  resource-exhaustion advisories reported against 8.11.2. It is not shipped in the
  application bundle. Neither npm update changes a direct dependency version.

These fixes are tracked in [#169](https://github.com/ncecere/grounded/issues/169).
This release does not add a feature, change a setting or add a migration: the
schema stays at **53**. Fixes to the remaining v0.6.0 QA tracking lists are separate
work; these notes do not claim they are resolved.

## Upgrade

Take or verify a backup and follow the [upgrade guide](../operations/upgrades.md).
Once this release is published, update the remote Kustomize ref from `v0.6.1` to
`v0.6.2` and pin **both** `grounded` and `grounded-ocr` to the release's published
digests. Do not deploy a candidate based only on these notes. A rolling upgrade
from v0.6.1 needs no new configuration.

The fix is in the compiled dependencies: rebuilding an affected checkout with
the old Go toolchain or old x/net does not include both fixes. Use the updated
module/toolchain pins or the verified published images.
