# Grounded v0.6.2

A security patch for dependencies found during fresh source and image scans.
There are **no new features, migrations or settings**: the schema stays at **53**.
The remaining v0.6.0 QA tracking lists are separate work and are not claimed as
resolved by this release.

## Security fixes

- **Go 1.26.10: GO-2026-6809 (`crypto/x509`).** Certificate verification rejects
  known intermediate certificates that are no longer trusted, including cases
  where the system trust store has not been updated. The previously pinned
  Go 1.26.9 is affected; the scanner found a reachable verification path through
  an outbound MCP response body read.
- **golang.org/x/net v0.62.0: GO-2026-6860.** Avoids quadratic text-node coalescing
  while parsing HTML. Grounded's HTML ingestion reaches the affected parser
  through `htmlmd.Convert` and goquery; v0.61.0 is affected.
- **go-jose v4.1.6: CVE-2026-116587.** Fixes denial of service while parsing
  RSA JWKs. The image scanner found this fixable high-severity finding after
  the reachable-code scan was clean; it was patched and the image rebuilt.
- **seroval 1.7.3 (shipped, through TanStack Router).** Fixes serialization
  injection advisories GHSA-f86p-h4j2-7qgj and GHSA-9wx9-5pv9-3349 present in the
  previous 1.6.9 lockfile entry. This is a preventative dependency update; the
  audit alone is not evidence of an exploitable Grounded feature.
- **undici 8.12.3 (development-only, through jsdom).** Fixes the HTTP/TLS and
  resource-exhaustion advisories reported against 8.11.2. It is not shipped in
  the application bundle. Neither npm update changes a direct dependency version.

Tracked in [#169](https://github.com/ncecere/grounded/issues/169). Two existing
calendar-dependent UI assertions were also made stable (#172); application
behavior and test coverage are unchanged.

## Upgrading from v0.6.1

Take or verify a backup and follow the [upgrade guide](../operations/upgrades.md).
Update the remote Kustomize ref from `v0.6.1` to `v0.6.2` and pin **both**
`grounded` and `grounded-ocr` to the digests published with the release. A rolling
upgrade needs no new configuration.

The fixes are in compiled dependencies: rebuilding an affected checkout with
the old Go toolchain or old dependency pins does not include all fixes. Use the
updated pins or the verified published images.

## Validation and known limitations

The [validation record](../security/validation/v0.6.2.md) identifies the candidate
source and exact image digests, completed checks and the remaining publication
gates. Completed candidate checks include clean Go/npm source scans, full local
lint/unit tests, all 1,196 UI tests, the v0.6.1 upgrade rehearsal, cluster doctor,
and an admin/user QA walk at desktop/mobile widths (94 captures, no failures under
the configured rules). These are mechanics and regression checks, not claims of
real-model answer quality or real-IdP acceptance.

The rebuilt candidate has **no Go image findings** and **no fixable high/critical
findings** in either image. The OCR image still has unfixable Debian findings;
read the [scan results and reachability assessment](../security/dependencies.md).
It is **not** vulnerability-free. OCR egress hardening (#77) remains open.

Required CI must pass before merging. Before tagging, main's image and upgrade
pipeline must pass. The tag pipeline repeats the required checks, builds, scans
and signs both images, and publishes digests, SBOMs and checksums; verify those
exact release artifacts rather than treating a candidate digest as a release.

## Verifying the images

Follow [the image verification guide](v0.2.0.md#verifying-the-images), using
`v0.6.2` and the exact digests from this release's assets. Verify the checksums,
signatures, provenance and that the binary reports `grounded v0.6.2 (…)`.
