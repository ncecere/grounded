# Grounded v0.6.3

Published **2026-10-30** at source `a55dc5e50ab011092ddf6f480891aa3828bf462d`:
[v0.6.3](https://github.com/ncecere/grounded/releases/tag/v0.6.3). The
[validation record](../security/validation/v0.6.3.md) distinguishes candidate checks
from the completed final-main and published-artifact verification.

This patch finishes the v0.6.0 QA fixes for the API, chat, editor/owner and new
feature tracking lists, and hardens OCR networking. It introduces no new retrieval
mode. The opt-in fuzzy-boilerplate and structured-table work is separate and is
not included in this patch's scope.

## Changes for people and integrations

- **REST methods and OpenAI errors follow the contract.** A wrong method on a
  known path returns `405` with `Allow`; an unknown path stays `404`. OpenAI-shaped
  errors also cover shared authentication, session, CSRF, rate-limit and
  pre-header panic handling, preserving `Retry-After` and internal-error
  redaction. `OPTIONS` grants no cross-origin write permission. (#116)
- **Invalid inputs name the public field and expected format.** Invalid email,
  date/date-time and UUID text use `invalid_email`, `invalid_date` and `invalid_id`;
  malformed JSON, unknown fields and wrong JSON kinds stay `invalid_json`. Agent
  configuration errors no longer expose Go type names. Text-only OpenAI messages,
  the 51-message submission limit, and explicit retrieval `topK` from 1 to 50 are
  enforced. Bearer scheme names are case-insensitive; secrets are not. (#119)
- **New display labels and upload filenames reject invisible controls.** Teams,
  agents, knowledge bases, sources, keys and explicit conversation titles cannot
  hide or reorder their identity with control, formatting or default-ignorable
  characters. Upload filenames are rejected before storage, not silently renamed.
  Existing names are not rewritten. Ordinary letters, combining marks and
  variation selectors remain allowed; joiner-based scripts and emoji need a
  label without the joiner. This is not protection against every confusable.
  Initial conversation titles omit hidden characters without changing the
  question or history. (#119)
- **Two chat tabs catch up without replacing a live answer.** Returning to a tab,
  or completing its answer, merges the stored transcript in server order. A
  `?c=null` link shows the unavailable-conversation notice. (#128)
- **No-op changes stay no-ops.** An unchanged source PATCH preserves revision and
  audit history; publishing an unchanged agent draft returns `409 no_changes`.
  Suggested slugs transliterate accented, Greek and Cyrillic letters and avoid
  unusable one-character addresses. (#132)
- **Team-request approval needs an active owner.** A suspended proposed owner is
  flagged before approval; a reviewer must choose another owner or receive
  `409 owner_suspended` with no team created. Requesters see the classification
  actually approved. Template names are unique under Unicode-aware lowercase,
  rather than the database's C-locale ASCII-only lowercase. (#140)
- **Withdrawn webhook destinations stay blocked.** Existing webhooks can be
  edited or disabled, but not enabled or delivered to an unapproved destination.
  Invalid DNS label/name lengths are rejected and long host patterns wrap. A
  router's Share dialog explains up front when its routed conversation cannot be
  shared, and Markdown exports name the agent that answered. (#140)
- **Admin limits and guidance are explicit.** The public message-length limit
  must be at least 1; use the public-access switch to disable chat. Limit batches
  must include `default` and `ceiling`, with explicit null retaining its
  unlimited/inherit meaning. Ordinary resource limits still allow zero. Auditors
  receive 403 before admin-write body/revision validation, while permitted
  read-only previews remain available. Re-inviting an address renews its existing
  open invite, resends the email and records a distinct renewal audit event.
  Features links re-anchor after async settings finish loading, and SystemOne
  remains visible in Models even before setup. (#146)

The CHANGELOG has the smaller wording, phone-layout, validation and crawl fixes.
In particular, known download extensions are skipped without a request; an
extension-less download can still require a fetch. These fixes are not a claim
that every slow crawl is explained.

## OCR networking

The Tesseract component now has **deny-all egress, including DNS**. The base DNS
policy excludes OCR, because Kubernetes NetworkPolicies combine by union. API
and worker ingress is unchanged. A kind enforcement test exercises the standalone
component and composed base, permitted callers, denied unrelated callers, and a
live DNS-policy mutation. Custom namespace-wide allow policies must exclude OCR
as well. (#77)

## Database and upgrade preparation

The planned schema is **55**, up from 53 in v0.6.2:

- **00054:** uses PostgreSQL's ICU `und-x-icu` collation to rename existing
  case-colliding template names with numbered suffixes, preserving IDs,
  configuration and agents made from them. It adds a **non-unique** lookup index;
  the old unique index remains. New application writers enforce Unicode-folded
  uniqueness under a transaction-level advisory lock. The stricter unique index
  is deliberately deferred to a later release, following the staged-migration
  policy. Old v0.6.2 pods may still save Unicode-only twins during a rollout or
  after an image rollback; their behaviour is not turned into a 500 by a new
  constraint. This migration takes a template-table write lock during deduplication
  and index creation. It checks ICU support before changing anything; custom
  PostgreSQL builds must provide the collation. Follow the upgrade guide's
  reindex guidance after database-server ICU changes.
- **00055:** adds the approved classification to team requests with a constant
  empty default, **without a table-wide backfill**. For an approved legacy request
  or one approved by an old pod during rollout, the new API resolves the empty
  value from an indexed approval-audit lookup, then the team's level, then the
  requested level. New approvals store the true approved level directly.

The candidate rehearsal from v0.6.2 passed, including old/new reads and writes
on schema 55, Unicode template-name collisions and old-pod approvals. Its repair
and fail-before evidence are in the [validation record](../security/validation/v0.6.3.md).
The exact final-source main and tag pipelines subsequently passed, and the
published images and assets were independently verified. Candidate and published
results remain separately identified in the validation record.
Follow the [upgrade guide](../operations/upgrades.md), verify a backup, update the
Kustomize ref and pin **both** application and OCR images to the published digests.
No production deployment is part of preparing or publishing this release.

## Validation and known limitations

The dependency/licence inventory, initial Go/npm/source scans, candidate upgrade
rehearsal and disposable-environment doctor and desktop/mobile walk are complete.
The walk made 94 captures with no configured-check failures; representative
screenshots, not every capture, were visually reviewed. Initial source scans have
zero Go/npm vulnerabilities and zero secrets, with the existing reviewed IaC
findings retained.

The runtime candidate also passed main CI and independent signed-image checks on
amd64 and arm64: zero Go findings and zero fixable HIGH/CRITICAL findings. It
retains four UNKNOWN app advisories (certificate/timezone-data updates) and 341
OCR Debian findings without a published fix in the scan. These are **not
vulnerability-free images**; see the validation record for digests and the
reachability assessment.

Final main and tag CI, published checksums, signatures, SBOMs, source/platform-bound
provenance and actual amd64 versions all passed independent verification. The
published indexes have the same documented residual counts on both architectures;
see the validation record for their immutable digests. No ARM hardware execution,
real-IdP acceptance or production deployment is implied.

Fake-model tests establish mechanics, not real-model answer quality. Retrieval,
adoption, compliance, scale and connector issues remain separate work. This is a
pre-1.0 patch, not a v1.0 readiness declaration. Existing limitations in
[v0.6.1](v0.6.1.md#known-limitations) remain unless a change above explicitly
resolves them.
