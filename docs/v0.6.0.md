# v0.6.0: service desk building blocks

Status: **released** (2026-10-16; [`releases/v0.6.0.md`](releases/v0.6.0.md)); the design of each item as built is in [`specs/v0.6.0/DESIGN.md`](specs/v0.6.0/DESIGN.md). Scope and the main decisions (owner, 2026-10-04) below. Planned ahead of v0.5.0 ("better knowledge in") so the next versions are mapped to the roadmap ([`roadmap.md`](roadmap.md) § L). Decisions are recorded here as the owner makes them; the full design is written before building.

## Scope (owner, 2026-10-04)

| # | Item | Roadmap |
|---|---|---|
| 1 | **Webhooks**: signed, retried events for other systems | F3 |
| 2 | **Agent templates**: good starting points for common agents | C4 |
| 3 | **Router agent**: one front-door agent that sends each question to the right team's agent | C5 |
| 4 | **Conversation sharing**: a read-only, revocable link to your own conversation | C12 |
| 5 | **In-app team requests**: a form with admin review, **optional** (off until a platform admin turns it on) | E3 |

Not in v0.6.0: human handoff and ticketing (C3; owner: no ticketing integration for now).

## Decisions

### Webhooks

- **Who sets them up (option A):** platform admins turn webhooks on and approve destinations (an allowlist like the crawl allowlist; private, loopback, link-local and metadata addresses refused); team admins and owners create webhooks for their own team's events, to approved destinations only; platform admins also get platform-wide events. Every webhook and every change is audited.
- **What they carry:** IDs and summaries, never transcripts or document text; a receiver that needs more fetches it through the API with a key, so classification rules and permissions still apply.

### Agent templates

- **Where they come from (option A):** Grounded ships 4–5 generic built-in templates (service desk FAQ, policy explainer, course helper, public website assistant, internal knowledge assistant), and a **platform admin can save any agent as a platform-wide template**: its instructions, model choice, answering mode, safety, SystemOne checks, Advanced settings, appearance and starter questions, **never its knowledge bases, sources or tools' credentials**. Teams pick a template when creating an agent. Team-level templates may come later if teams ask.

### Router agent

- **What it routes to (option A):** agents whose team turned on **"Can be reached through routers"** (off by default, per agent), and only those the asker could open themselves (a public router reaches public agents; a signed-in router also reaches signed-in agents). The answer names the agent that answered, with a link to continue there. When no agent fits, the router says so and the question counts in the router's gap report.

### Conversation sharing

- **What a link shows, to whom (option A):** a read-only **snapshot** of the conversation at the moment it was shared (questions, answers and their citations), visible to anyone **signed in who may use that agent**; citations open only passages the viewer may see. The owner revokes a link any time, and it ends with the conversation's retention. For a **public** agent, the owner may also make a link open to anyone. The snapshot leaves out the sharer's name unless they tick **Show my name**, and never includes feedback or reasoning. This changes ADR-0010 (conversations are private to their owner): an amendment is part of the design.

### In-app team requests

- **How they work (option A):** anyone signed in can request a team (name, purpose, owner, the classification it needs); platform admins get a notification and a review queue in Admin → Teams; approving creates the team with the requester as owner (optionally from an agent template), declining sends a reason. Admins can limit who may request (for example by SSO group) and how many open requests a person may have. Everything is audited.
- **A suspended owner is never given a team.** If the person who would own the team (the requester, or the person they named) has a suspended account, the Approve dialog says so up front and **requires a different owner** (`ownerEmail` on the approve call); the API refuses with `409 owner_suspended` and creates nothing. The person who asked is told when someone else owns the team. The requester's page shows the classification the reviewer **approved** (and what was asked for when it differs).
- **A platform switch (owner):** **Team requests** in Admin → Settings → Features, **off by default**. A platform admin can turn it on and off at any time: off hides the request form everywhere and refuses new requests (the API too), and open requests stay in the review queue until handled. With it off, team creation stays with platform admins, as today.
