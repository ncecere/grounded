# Signed daily audit export — proposed detailed design

Written before implementation against private source
`405da0a05c37f89989c314ce20dfd608e3fdf98d`. ADR0034 is Proposed.

## Scope and implementation boundary

This document specifies the engine first. The engine produces actual signed JSONL
objects in private blob storage, retrieves them and verifies them offline. It is
not yet a usable Admin Audit product increment: API/settings, River scheduling,
UI and their authorization/contract/accessibility gates remain required. Nothing
registers the engine in application startup, so the feature is OFF. No key is
loaded or generated by the application. No new general CLI or SDK is proposed.
External-S3 destination approval/transport and SIEM streaming are not implemented.
Only the install's existing private blob Store is supported; an explicit external
mode must fail closed, never silently select built-in storage.

## Snapshot and range

A request names an exact UTC midnight and rejects today/future days. A repeatable
read transaction, serialized against other requests through a short singleton
row lock, freezes *visible* rows of [midnight, next midnight) ordered by numeric
source ID into dedicated projection rows. Pages contain at most 256 rows. No
object-store/network operation occurs in the transaction. This is a snapshot,
not a guarantee that every transaction with an old occurred_at has committed.
The manifest records transaction start time (not a commit timestamp) and source
high-water ID. Late commits
are excluded, not silently substituted on retry. Retention can delete source rows
later without changing frozen facts. Identity-sequence holes are normal (rollback,
retention, other days); source IDs must increase but need not be consecutive.
Contiguous export ordinals plus manifest count detect removal/duplication within
an artifact. This does not prove pre-snapshot source completeness.

One durable export per day; a duplicate request returns its original identity.
After the first day, requests must be exactly the following UTC day, including
empty days. The previous export must be committed. This prevents chain branches
and date gaps. Empty days have zero bytes, zero records, empty final chain and
the SHA-256 of empty bytes. The first export anchors explicitly with an empty
previous-manifest hash; an external witness must record this anchor.

## Deliberate safe projection

Inventory: `audit.Entry` serializes Before/After through arbitrary JSON;
`authz.Actor.Audit` adds API-key/OAuth metadata; `httpapi.toAPIAudit` exposes raw
states/metadata plus resolved email, display name and target labels.
None of these serializers is reused. The export reads only numeric ID, timestamp,
actor kind and UUID, team UUID, action, target type, and target ID. Metadata is
not selected at all. Action/type accept bounded lowercase protocol identifiers;
unknown unsafe identifiers become the fixed `redacted` marker. Target ID is kept
only when a UUID; arbitrary targets (URLs, patterns, settings keys, names) become
empty. Before/after, metadata (including encoded strings), request ID, client IP,
labels, emails, document/conversation text and instructions are omitted entirely.
This authenticates projected facts, **not** a checksum of the source database row.
No source-content tables or model/provider calls are made. Failures use constant
messages, never raw values. Actor kind distinguishes user/API-key/system; OAuth
attribution and safe nonsecret metadata need a separately reviewed allowlist.

## Canonical bytes and signature

Format `grounded.audit.v1`: Go encoding/json on fixed structs in declaration order,
compact UTF-8, default HTML escaping, no optional keys, RFC3339Nano UTC timestamp,
base-10 signed 64-bit source IDs/ordinals, UUID lowercase strings (or empty).
Each line has ordinal, fact and previous line hash; append one LF. SHA-256 covers
that complete line including LF. First previous hash is empty. Payload SHA-256
covers all emitted bytes. A fixed struct manifest binds version, UTC day,
snapshot time, watermark, count, first/last IDs, final chain hash, payload digest,
previous signed-envelope digest, algorithm, and key ID. Key ID is the lowercase
SHA-256 fingerprint of the raw 32-byte Ed25519 public key. Ed25519 signs
`grounded.audit.manifest.v1\n` followed by exact compact manifest JSON. Envelope
holds manifest, base64 raw public key and base64 signature. Its exact compact JSON
is hashed for next-day linkage. Key rotation changes key ID; next manifest still
links the previous envelope hash. Missing/malformed private keys fail closed.
Only caller-supplied disposable fixtures are generated in tests.

Verification requires a separately trusted key-ID/public-key mapping, not trust
in the key bundled with the envelope. Reject noncanonical lines, unexpected
fields, reordered/missing/duplicate ordinals, nonincreasing source IDs, day/range
mismatches, line-chain/hash/count mismatches, wrong key and modified manifests.
The verifier is bounded to 16 KiB per JSONL line. Check previous envelope hash
and next UTC date for a sequence. Missing first/latest artifacts require an
external checkpoint; a signature alone cannot reveal an unknown suffix deletion.

## Publication and retry atomicity

The built-in Store.Put overwrites; neither FS nor S3 Store exposes conditional
create. HEAD+PUT is not used and is **not** a no-overwrite primitive. Each attempt
writes to a newly random UUID prefix, never a committed key. Payload is spooled
to a mode-0600 temporary file (bounded RAM, disk proportional to day), then uploaded.
The envelope is committed with object key in one CAS of pending → completed.
Concurrent attempts may upload separate copies; one wins, losers are unreachable
orphans. A crash before CAS leaves pending and may orphan a complete object; a
retry uses the same frozen facts and linkage, and a fresh key. A crash after CAS
returns the original committed export. No database locks span blob I/O.
Orphan cleanup and explicit bounded failed/retry state are still integration work.
No exactly-once network or distributed transaction is claimed. Blob durability
and access policy remain the install's responsibility; no public ACL/presign URL.

## Required integration before owner review as usable increment

OpenAPI FIRST: admin-only revised settings approval and explicit request/resume;
platform admin/auditor list, manifest/verification info and payload download.
All operations reject team, personal, OAuth and publishable keys under existing
platform policy (even keys owned by a platform admin); no cross-tenant grant.
Use If-Match (428/412), transactional audit with fixed export IDs/day/counts only,
and River InsertTx in the same request transaction. A periodic job may request
one closed day at a time only while explicitly enabled; GETs must perform no work.
Download resolves committed export ID, never request-provided paths, with private
no-store, nosniff, safe constant attachment name, and no signing secret response.
Admin Audit should show off/pending/completed/failed and read-only auditor facts;
admin config/create controls only, no work on mount. Add every route to authz
matrix, regenerate types normally, test 390px/keyboard/axe and all failure states.

Tests must include actual PG17 snapshot consistency, empty day, large paging,
concurrent request/publication, lost upload acknowledgement, crash/retry,
rotation/linkage/corruption/truncation/gaps, canaries and old ordinary writers.
No claim of full issue #39 acceptance: streaming follows separately.

## Offline standard signature procedure

Keep an independently witnessed previous envelope hash and key fingerprints.
Retrieve payload and canonical envelope through the eventual authorized download
API (not yet implemented). Independently pin the raw public-key SHA-256; never
accept the envelope's bundled key as approval. For standard OpenSSL verification:

1. Parse the envelope JSON. Serialize its `manifest` object in the exact field
   order above, compact with no spaces, no trailing LF. Prefix the UTF-8 bytes
   with `grounded.audit.manifest.v1` and one LF; save as `signed.bin`.
2. Base64-decode `signature` to `signature.bin`. Convert the **trusted** raw
   32-byte public key to Ed25519 SubjectPublicKeyInfo DER by prefixing hex
   `302a300506032b6570032100`; save as `trusted-public.der`.
3. Run `openssl pkeyutl -verify -pubin -keyform DER -inkey trusted-public.der
   -rawin -in signed.bin -sigfile signature.bin` (one shell command).
4. Compare `sha256sum payload.jsonl` to `payloadHash`; then validate every
   canonical line/ordinal/source ID/day and previous-line hash as specified above.
   `internal/auditexport.Verify` implements this bounded streaming validation.
5. Validate the previous canonical envelope SHA-256 and date adjacency;
   `VerifyLink` checks these. Independently reconcile the first/latest checkpoint.

OpenSSL signature success alone does not validate payload structure, coverage,
source completeness, chain continuity or freshness. No compliance certification
is asserted.
