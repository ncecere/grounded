# v0.4.1: small wins

Status: **being designed** (owner, 2026-10-02). A patch release after [v0.4.0](releases/v0.4.0.md): the roadmap's "small wins" (§ K). Grounded stays one MIT project ([ADR-0025](adr/0025-community-and-enterprise-editions.md), rejected).

Each item lists what exists today (from the code), the proposal, and the open questions. Decisions are recorded here as the owner makes them.

## 1. Follow-up suggestions (C8)

**Today.** Agents have up to 6 static starter questions (`agents.starter_questions`), shown on an empty chat and after a refusal ("You can ask:", `web/src/pages/chat/notes.tsx`). Nothing is suggested after a normal answer.

**Proposal.**
- After an answer with citations, the agent's chat model writes **up to 3 follow-up questions** that the passages it retrieved can answer (it sees the question, the answer and the passages' titles and headings, not the whole conversation). Questions the passages can't answer aren't suggested: the point is a next question that gets a grounded answer, not a chatty prompt.
- A separate, small call after the answer has ended (reasoning effort Off or Low when the model accepts it), so the answer, its citations and its checks are untouched and nobody waits for it: the answer is done, and the suggestions appear a moment later under it, as `Suggestion` chips. Choosing one asks it.
- A new SSE event `suggestions` after `message_end` / `citations_checked`, before `done`. Not on the OpenAI-compatible endpoint or MCP `ask` (no UI to show them).
- **Moderation:** suggestions are model text, so in the Buffer and Stream checked paragraphs modes they're checked like an answer (one call for all three) and dropped, silently, if the check fails. In Stream, then retract, they're checked too (they appear only after the check).
- **Not after** a refusal (the starters show there), an answer with no citations, or a moderated answer.
- **Saved answers** store the suggestions with the answer and replay them.
- Metered as chat tokens with the feature `suggestions` (Costs and analytics), like query rewrites.
- A per-agent setting in **Build → Advanced**, versioned with the agent.

**Questions.** Q1: on by default? Q2: one call after the answer, or ask for them inside the answer?

## 2. Warnings about expectations a knowledge base can't meet (A14)

**Today.** While typing an evaluation question, Grounded warns when an expected document isn't indexed (or is deleted) and when a must-mention phrase appears in no source (`POST /v1/teams/{team}/evaluation-question-check`, `internal/evals/presence.go`); CSV imports get the same warnings. Nothing checks a whole set later, after documents change. A run that misses an expected document looks 50 results deep and records the rank it found (or none) in the result's diagnosis.

**Proposal.**
- **A set-level check:** the set page lists the questions whose expectations the knowledge base can't meet today (expected document not indexed or deleted, phrase in no source), as a "Needs attention" filter and a count in the header, recomputed when the page opens (the same check, run for every question; sets hold at most a few hundred).
- **Out of reach:** a question whose expected document wasn't found in the top 50 in each of its **last 3 runs** is marked "Expected page not found in the top 50 (last 3 runs)", with a link to the latest result's diagnosis. It means the page is there but retrieval never surfaces it: a chunking or wording problem, not a model one.
- Before a run starts, the run dialog says how many questions can't be met ("4 questions can't pass: their expected pages aren't indexed"), without blocking it.

**Questions.** Q3: the 3-run window and the top-50 depth.

## 3. OCR follow-ups (B12)

**Today.**
- A TIFF is read with `golang.org/x/image/tiff`, which decodes the first page only; a multi-page TIFF gets a warning ("only the first page … was read").
- "Needs OCR" (`needs_ocr`) is set only on PDFs with no text at all. A **partly** scanned PDF is indexed (`ready`) with a warning to delete and re-upload it once OCR is on; **Retry all that need OCR** doesn't include it.
- The kind smoke test (`make k8s-smoke`) deploys Grounded without the OCR sidecar; the sidecar's own tests run in the `ocr` CI job.

**Proposal.**
- **Every page of a TIFF:** each page is decoded by pointing the TIFF header at that page's image directory (a header rewrite, no new decoder), then recognised like a scanned PDF page, up to the same page limit as PDFs.
- **Partly scanned PDFs join the retry:** the parser records which pages had no text; when OCR is on, **Retry all that need OCR** (and a document's own **Retry with OCR**) re-parses them, OCR'ing just those pages. The warning changes to say so.
- **The sidecar in the smoke test:** `k8s-smoke` builds the OCR image too, deploys the `ocr-tesseract` component, turns OCR on, uploads a one-page scanned sample and waits for its text.

**Questions.** None expected; Q4 only if the smoke test gets much slower.

## 4. SystemOne capacity (A12)

**Today.** All SystemOne calls share one first-come-first-served limit per connection (`max_concurrent_requests`, default 8). Interactive callers (judging, scope, claim checks, moderation, saved-answer confirmation) wait behind background ones (the gap topics job's grouping checks, evaluation runs going through the agent pipeline). The request-duration metric starts after a slot is free, so waiting is invisible. The admin SystemOne page shows each feature's median added time; the agent editor only says "Each adds a little time per answer".

**Proposal.**
- **Two priorities:** interactive and background. A freed slot goes to an interactive call first; background calls may hold at most half the slots, so a busy evaluation run or gap job can't fill them.
- Evaluation runs and the gap topics job run at background priority (a context flag, carried into the agent pipeline).
- **Waiting is measured:** `grounded_systemone_wait_seconds{feature,priority}`, a panel on the Models and moderation dashboard, and the metric help text lists every feature.
- **The agent editor shows the cost:** each SystemOne check in **Build** shows the platform's median added time ("Adds about 0.4 s"), from the numbers the admin page already has.

**Questions.** Q5: half the slots for background work.
