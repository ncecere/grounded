# Dependencies, SBOM and scan results

## The SBOM

Every image published by CI (`.github/workflows/image.yml`, on pushes to `main` and `v*` tags) is built by BuildKit with `sbom: true` and `provenance: mode=max`. The SBOM (SPDX, generated by BuildKit's Syft scanner) and the SLSA provenance are attached to the image in the registry as attestations, for each platform. The image is then scanned by Trivy and signed with cosign (keyless, bound to the workflow's identity).

Read them for an image digest:

```sh
IMAGE=ghcr.io/ncecere/grounded@sha256:...
docker buildx imagetools inspect "$IMAGE" --format '{{ json (index .SBOM "linux/amd64").SPDX }}' > sbom.spdx.json
docker buildx imagetools inspect "$IMAGE" --format '{{ json (index .Provenance "linux/amd64").SLSA }}' > provenance.json
cosign verify "$IMAGE" \
  --certificate-identity-regexp '^https://github.com/ncecere/grounded/' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

Since v0.2.0 each GitHub Release also carries them as files (`deploy/release/github-release.sh`): `grounded-<tag>-<os>-<arch>.sbom.spdx.json` for each platform, `grounded-<tag>.digest.txt` (the image reference by digest) and `checksums.txt` (SHA-256 of both; `sha256sum -c checksums.txt`). They are copies of the attestations of the digest the release names; the attestations remain the signed source.

The SBOM covers the whole image: the Go modules compiled into `/grounded` (read from the binary's build information), the web UI's packages as bundled, and the distroless base's Debian packages.

- **MPL-2.0: River** (`github.com/riverqueue/river` and its drivers, the job queue). The Mozilla Public License is weak, file-level copyleft: using it unmodified in a differently licensed program is fine, as long as its source stays available (it is, upstream) and its notices are kept. If River's files are ever modified, those modified files must be published under MPL-2.0.
