Failed runs and the causes found, kept for the record. Each fix was made in the code, not by rerunning until green:

- **#220:** "no work" tests counted River's periodic jobs. The tests now ignore jobs with `metadata.periodic`.
- **#222, #223 (CI):** two pre-existing faults surfaced and were fixed in their own PRs, each with a test that fails
  without the fix:
  - **#226:** a boilerplate refresh counted documents before an upload batch had finished indexing.
  - **#227:** with a small connection pool, a profile-migration preview could wait forever for a connection while
    holding the migration's lock. This also explains a CI timeout earlier taken for a slow runner.
- **#228 `k8s-smoke`:** the API and worker init containers deadlocked while migrating a fresh database. A migration
  waiting on a blocking `pg_advisory_lock` held a snapshot that 00066's `CREATE INDEX CONCURRENTLY` waits for. The
  lock is now polled with `pg_try_advisory_lock`. `TestConcurrentMigrationsOfAFreshDatabase` fails with the old lock.
- **#228 (key rotation):** the new encrypted column `audit_stream_destinations.auth_header` had no key-rotation
  seeder, so the rotation tests refused it. A seeder was added.
- **#228 (stream tests):** they waited for a number of delivered entries. Entries that began before the stream
  counted toward that number, because the start boundary is server-wide (`pg_snapshot_xmin`). The tests now wait for
  the named entries and check order and suffix.
- **#230 (on #229's code):** `TestFailureFinalizationHasABoundedCleanupBudget` reused its 100 ms budget for the
  recovery step, which can take longer on a loaded runner. Fixed in #232; 10 runs in a row passed with `-race`.
- **#231 (lint):** `NewServices` grew past the 100-line function limit, so the copier is now built with the worker's
  jobs.
- **Network failures, not code:** the `k8s` job failed twice on downloads. One was the datreeio CRD schema (#227); the
  other was `promtool` returning HTTP 504 (#228 and #230). The reruns passed.
- **GitHub refused pushes** to `docs/v090-status` (#230) with "fatal error in commit_refs_rules" while other branches
  pushed normally. The same commits continued as #233.
- **#234:** found while writing the release notes. If a concurrent build of 00066's index was interrupted, the
  migration kept the invalid index on the next run (`IF NOT EXISTS`). It now drops an invalid index of that name
  before building. `TestAuditTxidMigrationRebuildsAnInvalidIndex` fails on `main` without the fix.

## SCIM against a real identity provider

authentik 2025.10.3 was tested against a local `grounded serve` through a temporary tunnel, with development sign-in
off. Each of these worked:

- an existing user was linked rather than duplicated;
- a provisioned user was linked at first sign-in, audited as `auth.scim_link`;
- a group went to an SSO rule and then to team membership;
- a person deactivated in authentik was suspended about 20 seconds later;
- each change was audited.

No Grounded bug was found. Two authentik behaviours are now in the runbook:

- the provider must be assigned as a backchannel provider, or nothing is sent;
- the default email scope sends `email_verified: false`.

All test objects, the tunnel and the database were removed afterwards. Entra ID and Okta are covered by integration
tests of their documented PATCH shapes, not by a live tenant.

### Tag pipeline (run `42111478311`)

Passed: test, e2e, authz, ocr, k8s, k8s-smoke, helm-check, the app image and the release job. Two jobs failed with the
same error from cosign's keyless signing, which could not get its GitHub Actions OIDC token: `fetching ambient OIDC
credentials: invalid character 'u' looking for beginning of value`. GitHub's status page showed no incident.

- **OCR image, first attempt:** built, scanned and pushed as `sha256:7d5bbcc5a470c553d617a930ae23f2a7f4d4a956a32d073550dd6aaedecb9559`,
  then signing failed. That digest is **unsigned and has no tag**. Rerunning the failed job rebuilt the image and signed
  it as `sha256:6c95a590fad0c68cee30d6a45f5b9c61e0d2c50c1f31860f68fec18497434bf3`. The `v0.9.0` tag, the release asset and the chart job all use the signed digest.
- **Chart, attempt 1:** `helm push` published `ghcr.io/ncecere/charts/grounded:0.9.0` as
  `sha256:04ed1e77529661739d93c4f6c8fef2ae12c413034efc7a91e2642865e6092dad`, then `cosign sign` failed in the same way.
  `cosign verify` against the exact identity finds **no signatures**, so that digest is not a release artifact.
- **Chart, attempt 2:** refused by `publish.sh`, which never publishes over an existing version (`registry returned
  200`). The unsigned version has to be deleted before the tag's chart job can run again.
  [#237](https://github.com/ncecere/grounded/pull/237) makes this recoverable from the next tag: signing retries, and a
  rerun resumes an identical pushed chart.

No step was skipped and nothing was signed outside the tag's workflow.
