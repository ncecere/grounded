Failed or superseded runs, kept for the record:

- **#211:** the first CI run failed `TestListAuditCoversEveryTargetType`: the new `accessibility_settings` audit
  target had no live label in `ListAudit`. Fixed in `6ea91ec` (label in `audit.sql`, sqlc regenerated); the rerun
  passed. Before that, a review of the parked branch found that the UI sent `ownershipNote: ""` on every save, which a
  v0.7.0 API refuses as an unknown field. A rolling upgrade would have failed every agent save. The note is now
  serialized only when set (Go `omitempty`, and the UI omits it), and `tools/acceptance/about-upgrade.sh`'s
  legacy-codec test passes against the v0.7.0 source: a save carrying a note is refused, a stored note is never
  re-serialized, and saves without one are accepted.
- **#212:** the first CI run failed `helm-check`: `provenance.json` did not record the new `kind-lifecycle.sh`. It was
  regenerated (`generate.py` then `--check`: unchanged chart) and the rerun passed. After #211 merged, a conflict in
  the ADR index was resolved by merging `main` (both rows kept), and CI ran again on that head.
- **`main` after #213** (run `41774794658`, `34abb42`): `test` failed
  `TestBoilerplateFuzzyIsOrderIndependent`, a v0.7.0 test, on a web-only merge. The two sources' passages, dropped
  blocks and hashes were identical; only stored display samples of some near-duplicate variants differed, because a
  refresh reused text read under an earlier canonical document when pages arrived in batches (timing-dependent). Fixed
  in #215 (a sample is reused only while its canonical document is unchanged), with a unit test; the fuzzy
  integration tests then passed 15 times in a row locally. Not a rerun-until-green: the cause is in the code.
- **#213:** local web runs on a saturated machine timed out in `agent-build`, `palette-robustness` and
  `web-sources` (4 of 1301); those files pass alone (34/34), and CI passed.

## Helm chart lifecycle (kind)

`deploy/helm/scripts/kind-lifecycle.sh` on the #212 branch: kind v0.33.0, Kubernetes 1.37.0, kindnet enforcing
NetworkPolicies. The app image was v0.7.0 plus a throwaway fixture CA, pinned by digest from a local registry.
Postgres 17 (pgvector 0.8.7), Valkey, S3 (Silo, TLS) and an OIDC discovery fixture ran in a separate `datastores`
namespace. The chart reached Postgres and Valkey only through `namespace` + `podLabels` destinations.

| Step | Result |
|---|---|
| Install (1 API, 1 worker), restricted Pod Security | `grounded doctor` in api and worker: 13 checks, 0 failed |
| Values upgrade (2 + 2, new `appURL`) | doctor passes in both |
| Rollback to revision 1 | doctor passes; SQL marker kept |
| Negative control (Postgres pod labels match nothing) | doctor fails on `postgres connect` only |
| Restore | doctor passes |
| Uninstall | external database and marker untouched |

The cluster and registry were deleted on exit. Render checks on the rebased chart: `generate.py --check` (unchanged),
`test_chart.py` (7 tests, 14 schema negatives rejected) and `mutation.py` passed. `publish.sh`'s image-signature gate
(`cosign verify` with the exact identity `.github/workflows/image.yml@refs/tags/<tag>`) was checked against the
published v0.7.0 image with cosign v3.0.4 and verifies.
