## Decisions

### PII scanning at ingest

- **What a finding does (option A):** **flag by default**: a document with likely personal data (national ID numbers, payment card numbers that pass a checksum, and patterns a platform admin adds) is indexed but flagged ("3 possible ID numbers on page 4"), listed under Needs attention and in the content health report; editors review, dismiss or delete it. A platform admin can set a **classification level to block**: a flagged document at that level isn't indexed until an editor approves it. Matches are never stored in full or logged — only their type, count and page. Patterns first (fast, explainable, checksums against false positives); model-based detection may come later as an option.

### Audit export and SIEM streaming

- **How logs leave Grounded (option A):** a **signed daily export** of the audit log (JSON Lines with a checksum chain, so a gap or an edit is detectable) to the blob store or an S3 bucket, plus optional **streaming** in near real time to syslog (RFC 5424 over TLS) or an HTTPS endpoint (which Splunk's HTTP Event Collector and Elastic accept). Streaming destinations need a platform admin's approval, as webhooks do. Entries carry the audit log's fields (who, how they acted, what changed, when) and, like the log, never conversation or document content. No vendor-specific integrations.

### SCIM provisioning

- **What SCIM manages (option A):** users and their active status: the identity provider creates users before their first sign-in, updates names and emails, and **suspends** people who leave (sessions end, API keys and connected apps stop working, their conversations follow retention). SCIM Groups feed the existing **SSO group → team rules**, so team membership is decided in one place. A SCIM token per identity provider, scoped to SCIM only; every change audited.
