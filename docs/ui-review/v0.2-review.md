# v0.2 UX and answer review: synthesis

Sources: `tasks/REPORT.md` (10 tasks by role), `ia/REPORT.md` (inventory, density, naming, discoverability), `answers/REPORT.md` (15 questions, channels, mobile), and the orchestrator's own look (admin rail, Usage & limits, agent editor).

## Verdict

- **Not cluttered everywhere.** The v0.1 templates hold on most pages (one h1, one primary, "…" menu, tabs under the header). v0.2's clutter piles up in four places: the admin rail (24 items, the new Costs below the fold), the money pages (Costs Overview 2,320 px, Usage & limits 1,852 px, admin team Limits 1,542 px), the evaluation screens (8-level breadcrumb, a chart before the data, no expected-vs-got), and phones.
- **Actions are mostly easy once found.** Finding is the problem: spend lives in Team settings, budgets under "Limits", evaluations only as a KB or agent tab, the evaluations switch under Admin → Limits, and ⌘K has no team-side synonyms (spend, usage, evaluations, members).
- **Clarity is the weakest area.** Evaluation results can mislead ("Document deleted" for a typo; a bad answer passes on citations alone). Money shows six decimals. One concept has five names (Usage & limits, Costs, Limits, Budget, Spend), and "Test", "Try it" and "check" overlap.
- **Answers are grounded, but trust signals mislead.** No invented answers out of scope. But verification is per source, not per claim, and flips between runs. Uncited invented steps aren't flagged. A third follow-up isn't rewritten. Model punctuation breaks email links.

## Owner decisions needed

1. **Scope:** do the structural clean-up (admin nav regroup, money pages, evaluations IA, vocabulary) in v0.2 before the release, or ship v0.2 with the must-fixes and quick wins and do the structure in v0.2.1/v0.3?
2. **Track only with a budget:** today a Track-only team with a budget shows "No budget" (the agreed design: Track only has no budgets or warnings). Show progress against the budget without enforcing it?
3. **Admins and failed documents:** admins can't list or retry a team's failed or scanned documents (privacy by design). Allow a content-free list (team, source, count, reason, date) with "Retry OCR" and "Notify owners"?
4. **Verification per claim:** SystemOne chips are one verdict per source number; the eval score is per claim. Move chat to per-claim verdicts and flag uncited factual sentences (a larger change), or keep it and document it?

## Quick wins (small, no structural decision)

- Admin rail: collapsible groups, scroll the active item into view.
- ⌘K: team-side synonyms and deep links (spend, cost, usage, budget, members, API keys, audit, evaluations, try, OCR); plural and prefix tolerant; index agent descriptions; cap conversation hits at 3 with "More…"; dates on duplicate titles.
- Evaluations: runs table first, chart only with 3+ runs; breadcrumb trimmed (Team › … › Set › Run › Result); one "Score" column across KB and agent sets; question record's Delete into "…"; result list numbered 1–n.
- KB header primary follows the tab; "New question" secondary; empty states don't repeat the header primary.
- Vocabulary: agent "Test" → "Try it"; "Per-request checks" → "Requests"; run kinds "Retrieval / Full answer" (drop "check"); "Parsing" → "Parsing & OCR"; "Group mapping" → "SSO groups"; one time-zone note per page.
- Costs: Budgets row action "Change budget…"; the admin team tab is "Budget & limits"; the budget dialog explains each mode; "set on its page under Teams" is a link.
- Audit log: "Action" → "Area"; free text matches action labels; "System: group mapping" in Person.
- Chat: scroll to your message on send; offline send keeps the text with Retry; the thinking panel stays collapsed for end users; refusals from the scope check vs "searched, nothing found" worded differently, with the agent's starter questions; long user messages collapse.
- Mobile: rail as a drawer under 600 px, header actions collapse to primary + "…", chip tap targets ≥ 24 px, hide the keyboard hint on touch.
- Role explanation on the role badge; a new user without a team sees how to get one (owners or a help URL).
