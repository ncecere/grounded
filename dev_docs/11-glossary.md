# Glossary

| Term | Definition |
|------|-----------|
| **Agent** | A configured AI assistant with a system prompt, attached knowledge bases, retrieval settings, and a selected LLM model. Agents answer questions using RAG. |
| **Knowledge Base (KB)** | A container for ingested content. Chunks and vectors belong to a KB. An agent can search multiple KBs. Can be tenant-scoped or global (shared). |
| **Source** | A content origin attached to a KB. Types: `web` (scraped website) or `upload` (uploaded file). |
| **Source Run** | A single execution of content ingestion for a source. Tracks status, stage, and per-page results. |
| **Chunk** | A text segment extracted from source content. Stored in `kb_chunks`. Has associated vector embedding in pgvector. Default size: 800 tokens with 120-token overlap. |
| **Embedding** | A vector representation of text, generated by an embedding model. Used for semantic similarity search. |
| **RAG** | Retrieval-Augmented Generation. The technique of retrieving relevant context before generating an LLM response. |
| **Simple RAG** | Single-pass retrieval: embed query → search → prompt LLM with context. Fast. |
| **Advanced RAG** | Multi-step pipeline: rewrite query → plan sub-queries → parallel search → merge → generate. More comprehensive but slower. |
| **RRF** | Reciprocal Rank Fusion. Algorithm for merging ranked lists (vector + FTS results) into a single ranking. |
| **FTS** | Full-Text Search. PostgreSQL's built-in text search via `tsvector`/`tsquery`. |
| **pgvector** | PostgreSQL extension for storing and querying vector embeddings. |
| **Tenant** | An organization in the multi-tenant system. All data is tenant-scoped. |
| **Widget** | An embeddable Preact chat component that can be added to any website. Authenticates via widget token. |
| **Widget Token** | A public token that identifies an agent + tenant. Used by the widget for authentication without user credentials. |
| **Chat Endpoint** | A public token for programmatic chat access (API) or hosted chat pages. |
| **Hosted Chat** | A full-page chat experience served at `/chat/<token>`. No widget embed needed. |
| **BullMQ** | A Redis-based job queue library used for all background processing. |
| **Fairness Scheduler** | Distributes scraper worker capacity fairly across concurrent source runs. |
| **Drizzle ORM** | TypeScript ORM for PostgreSQL. Used for all database interactions. Type-safe schema definitions. |
| **Hono** | Lightweight, fast HTTP framework for the API server. Similar to Express but modern and typed. |
| **TanStack Query** | React library for managing server state (fetching, caching, synchronizing). |
| **Vercel AI SDK** | Framework for building AI apps. Used for streaming LLM responses and structured output. |
| **SSE** | Server-Sent Events. Streaming protocol used for real-time chat responses. |
| **System Admin** | A user with global admin access across all tenants. Manages AI models, system settings, and users. |
| **Soft Delete** | Marking a record as deleted (`deletedAt` timestamp) without removing it. Hard deletion happens after 30 days. |
| **Test Suite** | A collection of test cases for evaluating agent response quality. Supports automated scheduling and regression alerts. |
| **LLM Judge** | Using an LLM to evaluate whether an agent's response meets expected criteria. One of three check types in test suites. |
| **Prompt Analysis** | AI-powered analysis of test failures that suggests system prompt improvements. |
| **Enrichment** | Optional post-chunking step that uses LLM to extract tags, entities, keywords, and summaries for chunks. |
| **Reindex** | Re-generating all embeddings for a KB when the embedding model is changed. |
| **RLS** | Row-Level Security. PostgreSQL feature ensuring tenants can only access their own data. |
| **MCP** | Model Context Protocol. A standard for connecting LLMs to external tools and data sources. |
