# Grounded — Project Overview

## What Is Grounded?

Grounded is a **multi-tenant SaaS platform** that combines:

1. **Knowledge Ingestion (RAG)** — Scrape websites, upload documents, chunk and embed content for retrieval
2. **Configurable AI Agents** — Create agents with custom system prompts, attach knowledge bases, tune retrieval settings
3. **Embeddable Chat Widget** — A Preact-based widget that can be embedded on any website for end-user chat
4. **Testing & Evaluation** — Built-in test suites for evaluating agent quality with automated checks

The core design principle is **strict RAG with no hallucinations** — agents answer only from provided knowledge base context and cite their sources.

| Validation | Zod schemas throughout |
| Linting | oxlint |
| Containerization | Docker, Kubernetes |

## Key Design Decisions

### Multi-Tenancy
- Every data table has a `tenant_id` column
- API requests include `X-Tenant-ID` header for tenant context
- Row-Level Security (RLS) on PostgreSQL ensures data isolation
- Users can belong to multiple tenants with different roles

### Separate Vector Database
- Main PostgreSQL handles application data (schemas, metadata, chunks)
- A separate PostgreSQL + pgvector instance handles vector storage
- This allows independent scaling and different embedding dimensions per KB

### Worker Architecture
- Workers are separate processes that pull jobs from BullMQ queues
- **Scraper Worker**: Fetches web pages (HTTP, Playwright, Firecrawl)
- **Ingestion Worker**: Processes content through the full pipeline (extract → chunk → embed → index)
- Workers coordinate via Redis queues with retry, backoff, and fairness scheduling

### AI Model Configuration
- AI models (LLM + embedding) are configured via the Admin UI, not environment variables
- Supports multiple providers: OpenAI, Anthropic, Google, OpenAI-compatible
- Models are stored in the database and referenced by configuration ID
- Each knowledge base tracks its embedding model for consistent retrieval

## Quick Start

```bash
# 1. Clone and install
bun install

# 2. Copy environment config
cp .env.example .env
# Edit .env with your database passwords and session secret

# 3. Start infrastructure
bun run docker:dev

# 4. Run migrations
bun run db:migrate

# 5. Start all services
bun run dev
```

This starts:
- API server at `http://localhost:3001`
- Web UI at `http://localhost:5173` (proxied to `http://localhost:8088`)
- Ingestion worker
- Scraper worker

Login with the credentials from your `.env` file (`ADMIN_EMAIL` / `ADMIN_PASSWORD`).
